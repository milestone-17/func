## Purpose

保护用户存储在浏览器本地的财务数据不被意外丢失:通过请求浏览器持久化存储降低被自动回收清理的概率,并在用户长期未导出备份时温和提醒,形成"降低丢失风险 + 防止遗忘备份"的双重数据可靠性保障。

## ADDED Requirements

### Requirement: 申请持久化存储
应用启动时,系统 SHALL 尝试调用浏览器持久化存储 API(`navigator.storage.persist()`)请求不被自动回收;无论结果如何都不得阻塞应用启动或抛出未捕获异常。系统 MUST 将授权结果(已授权 / 被拒绝 / 浏览器不支持)持久化记录,并在设置页展示当前持久化状态。

#### Scenario: 浏览器支持且授予持久化
- **WHEN** 应用在支持 Storage API 的浏览器中启动,且 `persist()` 解析为 `true`
- **THEN** 系统记录持久化状态为"已授权",设置页显示"持久化存储:已开启"

#### Scenario: 浏览器支持但拒绝持久化
- **WHEN** `persist()` 解析为 `false`
- **THEN** 系统记录状态为"被拒绝",设置页显示"持久化存储:未开启",应用正常运行

#### Scenario: 浏览器不支持 Storage API
- **WHEN** `navigator.storage` 或 `persist` 不可用
- **THEN** 系统跳过申请、记录状态为"不支持",不报错,应用正常运行

#### Scenario: 申请过程不阻塞启动
- **WHEN** 应用启动
- **THEN** 持久化申请异步进行,主界面与数据加载不被其延迟或阻断

### Requirement: 记录最近备份时间
系统 SHALL 记录用户最近一次成功导出备份的时间戳(`lastBackupAt`)。导出备份成功后 MUST 立即更新该时间戳;该时间戳持久化存储,应用重启后保留。

#### Scenario: 导出备份后更新时间
- **WHEN** 用户成功完成一次"导出备份"
- **THEN** `lastBackupAt` 更新为当前时间,备份提醒(若存在)立即消除

#### Scenario: 时间戳跨重启保留
- **WHEN** 用户导出备份后关闭并重新打开应用
- **THEN** 设置页显示的"最近备份时间"仍为上次导出的时间

### Requirement: 备份到期提醒
当距离最近一次备份的时间超过提醒阈值(默认 30 天),系统 SHALL 在应用启动后于总览页温和提示用户"该备份了",并提供一键跳转到导出备份。提醒 MUST 非阻断(不挡住操作、可关闭)。从未备份过的用户在首次产生数据后达到阈值时同样触发。

#### Scenario: 超过阈值未备份
- **WHEN** 用户有数据,且距 `lastBackupAt`(或首次产生数据时间)超过阈值天数,且未处于"稍后提醒"推迟期内
- **THEN** 总览页显示备份提醒卡片,含"立即备份"按钮跳转设置页导出

#### Scenario: 未超阈值不提醒
- **WHEN** 距最近备份时间未超过阈值,或处于推迟期内
- **THEN** 不显示备份提醒

#### Scenario: 导出后提醒消除
- **WHEN** 提醒显示期间用户完成一次导出备份
- **THEN** 提醒立即消失,直到再次超过阈值

### Requirement: 稍后提醒
用户 SHALL 能对备份提醒选择"稍后提醒",推迟后系统在推迟周期(等于阈值天数)内不再提醒。推迟状态持久化,重启后保留。

#### Scenario: 用户选择稍后提醒
- **WHEN** 用户在备份提醒上点击"稍后提醒"
- **THEN** 记录推迟时间戳,提醒消失;在推迟周期内重启应用不再提醒

#### Scenario: 推迟期满重新提醒
- **WHEN** 推迟周期过去后用户打开应用
- **THEN** 备份提醒重新出现

### Requirement: 可配置的提醒阈值
系统 SHALL 允许用户在设置页调整备份提醒阈值(天数,合理范围如 7–180 天,默认 30),更改后立即生效并持久化。

#### Scenario: 用户修改阈值
- **WHEN** 用户在设置页将提醒阈值改为 14 天,且距上次备份已超过 14 天
- **THEN** 下次进入总览页显示备份提醒
