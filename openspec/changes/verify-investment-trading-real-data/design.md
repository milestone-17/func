# design.md

## Context

`investment-position-trading` 已实现加仓/减仓、超级转换、详情页、定投自动执行与 T+1/T+2 结算（见该变更 proposal/design/specs）。本变更为**真实数据回归验证**：用 `/home/wf/func-backup-20260813-0907.json`（16 只真实持仓，含净值）在沙箱环境端到端跑一遍新功能，断言投资页与永久页同步更新，测试后数据恢复原状。无行为变更（`skip_specs: true`）。

## Goals / Non-Goals

**Goals:**
- 用真实备份在一次性沙箱内完整执行：加仓、减仓（含全部卖出）、超级转换（含转入未添加基金）、周度定投自动执行
- 断言每步操作后：交易记录正确生成、持仓数量/均价/市值更新、投资页汇总与永久组合总额/分类占比同步、T+1/T+2 结算展示正确
- 验证结束恢复：沙箱销毁，备份文件与用户真实数据零改动
- 将核心流程固化为自动化 e2e（长期回归护栏）

**Non-Goals:**
- 不改动产品源码行为（这是验证，不是功能开发）
- 不在用户真实浏览器/真实 IndexedDB 上执行操作
- 不修改备份文件内容（只读使用）
- 不做性能压测或 UI 美学评审

## Decisions

### D1. 验证环境 = 一次性 Playwright 沙箱（复用既有模式）
沿用 `tests/e2e/app.py` 的 headless 浏览器模式：`page.route()` 拦截东财接口返回真实净值 fixture（从备份数据提取），`importAll(bundle, 'merge')` 导入备份，跑操作流。沙箱浏览器关闭即销毁 IndexedDB，**线上/真实数据零接触**。

### D2. 数据恢复语义 = 沙箱销毁 + 备份只读
「测试成功后恢复这个文件的数据」实现方式：备份文件全程**只读**（脚本读取用于导入，绝不写回）；验证产生的所有改动只存在于一次性沙箱的 IndexedDB，随浏览器关闭销毁。恢复动作 = 关闭沙箱 + 校验备份文件哈希/内容未变。真实用户数据本就不参与本次验证。

### D3. 操作流与断言矩阵（每个操作前后对照投资页与永久页）
- **加仓**：对某基金按金额加仓 → 断言 buy 交易生成、份额增加、均价重算、投资页总额增加、永久组合该分类市值同步增加
- **减仓（部分）**：按份额减仓 → 断言 sell 交易、剩余份额与均价正确、两页同步减少
- **全部卖出**：断言数量归零、持仓显示「已清仓」、永久组合市值扣除
- **超级转换**：转出持仓 A → 转入基金 B（含转入**未添加**基金自动建仓）→ 断言 sell+buy 双交易、B 持仓建立、A 清仓、投资页与永久页同步
- **周度定投自动执行**：绑定目标基金 → 打开应用触发 → 断言 buy 交易生成、持仓份额/市值增加、执行记录写入；重复打开不重复（幂等）
- **T+1/T+2 结算**：当日买入显示「确认中」不计入持仓/收益；次日（沙箱内推进日期）确认后计入

### D4. 日期可控性
结算与定投周期依赖「今天」。验证脚本注入可配置 `today`（覆盖 `new Date()` 的日期源），使 T+1/T+2 与周度周期断言确定化（产品侧提供注入点，见 `investment-position-trading` design 的 `todayISO` 约定；若无注入点，用沙箱内固定日期 + 断言「确认中」状态即可）。

### D5. 自动化固化
`tests/e2e/app.py` 增加独立 `s_trading()` 段：备份导入 → 加仓/减仓/转换/定投/结算断言 → 投资↔永久同步断言。用真实备份导出的 fixture（脱敏持仓 + 净值），不依赖真实网络。

### D6. 验证报告
脚本输出结构化对照表：每步操作 { 操作前投资总额 / 操作后投资总额 / 永久组合总额 / 分类占比 }，人工复核后归档。

## Risks / Trade-offs

- [备份含 16 只持仓、含真实名称/份额] → 仅本地一次性沙箱读取，fixture 用脱敏样本入库（沿用 `tests/fixtures/backup-holdings-20260813.json` 模式，不新增真实数据文件入仓库）。
- [转换到未添加基金需要真实净值] → 用备份内已有净值 fixture mock 接口返回，确定性可测。
- [日期推进在沙箱内不自然] → 优先用可注入日期源；若实现无注入点则退化为「验证确认中状态」+ 说明限制。
- [同步断言涉及浮点] → 所有金额以「分」整数比较，避免浮点误差。

## Migration Plan

1. 前置：`investment-position-trading` 完成（tasks 7.4 上线）后再执行本验证。
2. 步骤：扩展 e2e → 写验证脚本 → 沙箱执行 → 生成对照报告 → 校验备份文件未变。
3. 无线上/存储迁移：本变更不触碰 schema 与持久化。
